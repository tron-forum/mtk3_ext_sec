# 2. プロジェクトの作成手順
開発プロジェクトの作成手順を以下に示す。

## 2.1. プロジェクトのコンフィギュレーションと生成
### 2.1.1. プロジェクトの生成手順
e2studioを使用して以下の手順で、対象ハードウェアの開発プロジェクトの設定および生成を行う。

(1) メニュー[ファイル]から[新規]を選択し、対象マイコン(対象ボード)について、Project Type[TrustZone Secure Project]のプロジェクトを作成する。

(2) (1)で作成したプロジェクトに対し、開発するアプリケーションに応じたプロパティの設定を行ったうえでビルドする。

(3) 同様の手順で、Project Type[TrustZone Non-secure Project]のプロジェクトを作成する。その際に[Preceding Project]に(2)でビルドしたプロジェクトを指定する。

(4) (3)で作成したプロジェクトに対し、開発するアプリケーションに応じたプロパティの設定を行ったうえでビルドする。

以上でe2studioのワークスペースに、セキュア・プロジェクトと非セキュア・プロジェクトが出来上がる。
以降、セキュア・プロジェクトを`SecurePrj`、非セキュア・プロジェクトを`NonSecurePrj`と呼ぶこととする。

## 2.2. プロジェクトへのμT-Kernelの組み込み
e2studioを使用して以下の手順で、前項で生成したプロジェクトにμT-Kenrel 3.0およびセキュア機能拡張を組み込む。

### 2.2.1. セキュア・プロジェクトへの組み込み手順
(1) セキュア・プロジェクト(SecurePrj)のディレクトリに、セキュア機能拡張のmtk3_secureディレクトリをコピーする。サブプロジェクトのディレクトリ直下に置くこととする。
(2) Cコンパイラのプリプロセッサのシンボル定義に、対象ハードウェアの識別子を定義する（例：EK-RA8M1の場合は、識別子\_RA_EK_RA8M1_EXTSEC_を定義する）。
(3) Cコンパイラのインクルードパスに以下を定義する。
```
"${workspace_loc:/${ProjName}/mtk3_secure/config}"
"${workspace_loc:/${ProjName}/mtk3_secure/include}"
```
(4) アセンブラのプリプロセッサのシンボル定義に、(3)と同じ識別子を定義する。
(5) アセンブラのインクルードパスに、(4)と同じパスを指定する。
(6) mtk3_secureディレクトリのビルドを有効とし、セキュア・プロジェクトをビルドする。

### 2.2.2. 非セキュアアプリ・プロジェクトへの組み込み手順
(1) 非セキュア・プロジェクト(NonSecurePrj)に、セキュア機能拡張のmtk3_nonsecureディレクトリをコピーする。サブプロジェクトのディレクトリ直下に置くこととする。
(2) Cコンパイラのプリプロセッサのシンボル定義に、対象ハードウェアの識別子を定義する（例：NUCLEO-N657X0-Qの場合は、識別子\_STM32_NUCLEO_N657_EXTSEC_を定義する）。
(3) Cコンパイラのインクルードパスに以下を定義する。
```
"${workspace_loc:/${ProjName}/mtk3_nonsecure/mtkernel}"
"${workspace_loc:/${ProjName}/mtk3_nonsecure/mtkernel/config}"
"${workspace_loc:/${ProjName}/mtk3_nonsecure/mtkernel/include}"
"${workspace_loc:/${ProjName}/mtk3_nonsecure/mtkernel/kernel/knlinc}"
"${workspace_loc:/${ProjName}/mtk3_nonsecure/ext_sec}"
```
(4) アセンブラのプリプロセッサのシンボル定義に、(3)と同じ識別子を定義する。
(5) アセンブラのインクルードパスに、(4)と同じパスを指定する。
(6) `NonSecure/src/hal_entry.c`ファイルのhal_entry関数の先頭に以下のμT-Kenrel起動関数の呼び出しを記述する。
```C
  void knl_start_mtkernel(void);
  knl_start_mtkernel();
```
(7) mtk3_nonsecureディレクトリのビルドを有効とし、非セキュアアプリ・プロジェクトをビルドする。

# 3. アプリケーション
## 3.1. アプリケーションの場所
µT-Kernel 3.0のアプリケーションは、非セキュア・プロジェクトのディレクトリ下の任意の場所に置くことが出来る。
T-Kernel 3.0 セキュア機能拡張のGitHubリポジトリから公開しているサンプルプロジェクトでは、非セキュア・プロジェクトの直下にApplicationディレクトリを設け、そこにアプリケーションのプログラムを置いている。

## 3.2. サンプル・アプリケーション
T-Kernel 3.0 セキュア機能拡張のサンプルプロジェクトは起動すると以下の3個のタスクを実行する。

- task_1
  500ミリ秒ごとにボード上の赤LEDを反転する。
- task_2
  500ミリ秒ごとにセキュアAPIを呼び出す。セキュアAPIはボード上の青LEDを反転させる。
- task_3
  700ミリ秒ごとにセキュアAPIを呼び出す。セキュアAPIはボード上の緑LEDを反転させる。

また各タスクは実行開始時にボードのArduinoコネクタのUARTから、起動のメッセージ（文字列）を出力する。
